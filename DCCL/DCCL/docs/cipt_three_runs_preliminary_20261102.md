## 为什么固定学习率下，3800 与 5000 的前段也可能不同

在同一独立训练任务中，若模型/优化器初值、所有随机状态、样本顺序、
代码、硬件与数值环境、评估频率均一致，并且最大步数不参与损失或调度，
固定学习率的前 3800 步应一致。后面计划再训练 1200 步，不会倒过来改变此前更新。

此项目的实际行为是：train_all.py 在第 222–224 行只设一次 Python、
NumPy、Torch seed，然后第 341 行起依次训练四个目标域。每次 train()
都重新创建模型和优化器，但没有在每个目标域开始前重新固定随机状态。

因此改变 Art 训练长度，会改变 Cartoon 开始时的 RNG 状态；随后也会影响
Photo 和 Sketch 的初始化、采样及增强。这是随机状态的间接依赖，不是把
前一目标域模型的权重继续拿给后一目标域训练。相同的 seed=0 只规定进程起点，
不保证四个域的各自起点相同。

检查顺序：
1. 先比两组无对比实验的 Art 同步记录。若从 step 0 就不同，要先查实际配置、
   数据划分/文件顺序、源码/CLIP 权重、环境与初值；不能归因于“前一域多训练了”。
2. 若 Art 前缀吻合，后续域从 step 0 起不同，上述进程级 RNG 延续是明确候选原因。
3. 标量吻合只能支持轨迹相近，不能证明模型参数逐位一致；没有保存权重时无法做参数级证明。

当前与旧训练源码均已在最终 SWAD 评估附近保存/恢复 RNG，因此不能把这个
差异一概归咎于“打开 SWAD”。改变普通训练长度仍会消耗不同数量的随机数。

做严格步数消融时，建议每个目标域独立进程启动，固定同一个 seed、trial_seed、
域顺序/数据版本、代码与环境。不要用新的短跑结果自动当作长轨迹的截断。
当前实现 --steps 3800 / 5000 对应 step=0...3800 / 5000，共 3801 / 5001 次更新；
step 0 已经执行一次 update，不是零样本基线。

## 三列准确率到底表示什么

| 列 | 实际含义 | 当前用途 |
| --- | --- | --- |
| train_out | 三个源域各自 out 验证集准确率的等权平均 | IID 选 checkpoint |
| test_in | 未见目标域的 in 子集，默认约 80% | 当前 iid / last / SWAD 汇总所报告的数 |
| test_out | 同一未见目标域的 out 子集，默认约 20% | 当前 oracle 选点，也可读取 IID 点此列 |

两份目标子集均不参与梯度训练。不能把 test_in 当作训练准确率，
也不能把 train_out 当作训练样本拟合率。默认 evalmode=fast 下 train_in=0
是跳过评估的占位值。

当前源码使用：
`iid = records.argmax("train_out")["test_in"]`；
`oracle = records.argmax("test_out")["test_in"]`。
若论文统一采用 test_out 报告，应在同一 train_out 所选 checkpoint 读取 test_out，
并统一所有方法的口径。不要在 in / out 或 IID / SWAD 之间临时挑更高的列。

## 对比学习为何可能负向：当前代码能确认与不能确认的内容

新启动脚本指定 NR=1、温度=0.1、warmup=0、k=10、alpha=4。
实际执行值及负向发生在哪些域，要以待上传日志为准。

NR 代码只给原有 SupCon 的每个 anchor 重新赋权，
`w_i = 1 + 4 max(p_i(V)-p_i(E), 0)`，范围 [1,5]。
实现取 `mean(w_i * loss_i)`，不是 `sum(w_i * loss_i)/sum(w_i)`；
因此除重新分配样本关注外，整体对比项幅度也可能提高。
名义上的 contrastive_weight=1 并不意味着和不加权 SupCon 一样的实际优化强度。

正样本仍是合并 batch 中全部同类样本，包含同域同类；
跨域近邻只是算权重，不是强制只做跨域同类对齐。
每个源域 batch=32、三个源域合计96，批内近邻估计受类别构成影响。
warmup=0 又从第一次更新就施加完整对比约束。

由此存在几种需要日志验证的解释：
- NR 将较大权重给了小批量中噪声较大的“邻域退化”样本；
- SupCon 聚类目标与固定文本中心的对齐方向不完全一致；
- 同域正样本并不能保证跨域同类结构真正连通；
- 轨迹本身并未全面恶化，但 train_out 选到了目标更差的点。

这些是机制假设，不能在缺少两组原始记录时写成已经证实的梯度冲突或因果结论。
下一步会比较同一步、各自 IID 点与 Last/SWAD，并读取
`nbr_gap / nbr_pur_v / nbr_pur_e / nbr_wmean / dccl_contrastive_loss`。
单 seed 的小幅平均差异也不足以证明方法持续负向。

## 学习率与步数的暂定设置

先完成随机性与配置核查，再比较训练策略。保留所有损失权重不变：
1. 使用 5e-5 constant、3800 作为复现实验基准，暂不称其为最佳设置；
2. 固定预算3800，比较同样初始5e-5的 cosine 到0，再试1e-4 cosine；
3. 调度确定后比较3000 / 3800 / 5000，并用独立 seeds 复验少量候选。

当前 cosine 的 T_max 等于实际更新预算，改 steps 也会改衰减曲线；
这属于训练长度和衰减速度的联合比较。若要只研究训练长度，应保持相同
完整调度曲线再截断。选择超参数应使用预先声明的源验证规则，或源域内部
留一域验证来模拟 DG；当前目标域日志用于诊断和最终评估，不用于逐点挑最优预算。

现有低学习率旧日志没有支持“必须把步数继续加大”或“需要跳到2e-3”的证据。
在新两组日志到齐前，无法负责地定下三组排序、NR的净效应或最终最优步数。
